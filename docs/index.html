Why

Shipping often shouldn't stop at the end of the month.

On private repositories, GitHub-hosted minutes come out of a monthly quota, and Windows and macOS minutes cost more than Linux ones. When the quota runs out, CI, CD and releases stop. Self-hosted runners are free — the hard part is running many of them, reliably, on a machine you also use every day.

What's inside

The fixes you only find after running real CI at home.

sync-runners.ps1

Runner count control per repo: adds the missing, removes idle extras. Binaries checked by SHA-256.

per-runner Python

python-build-standalone in each runner's tool cache — parallel setup-python jobs, tkinter included.

Dev Drive

Runners on a ReFS Dev Drive with Defender performance mode, behind a junction — no path changes.

route_workflows.py

Rewrites runs-on for routing and skips cache restores on persistent runners.

dashboard + metrics

Projects, runners, queue time, failures and estimated billable minutes saved.

alerts

Windows notifications for offline runners, stuck queues and failures on the default branch.

job hooks

One JSON line per job and a clean TEMP before every job.

WSL hardening

Official Maven, apt lock queue, Maven file lock, a single wsl.exe holder.

Install

Ten minutes, two UAC prompts.

  1. Requirements: Windows 11, WSL 2 (Ubuntu), PowerShell 7, Git for Windows, Python 3.10+, and the GitHub CLI logged in with admin on your repos.
  2. Clone and configure: 
    git clone https://github.com/AllanSantos-DV/local-ci-forge
cd local-ci-forge
Copy-Item config\forge.example.json forge.json   # owner, repos, runner counts
.\install.ps1
  3. Route a repo and turn it on: 
    python tools\route_workflows.py C:\path\to\my-app     # review the diff, open a PR
gh variable set CI_RUNNER -b local -R you/my-app
  4. Watch it: python tools\dashboard.py --open — see the sample dashboard.
Private repositories only. On a public repo, a pull request from a fork would run untrusted code on your machine. Read each workflow before routing it: tests that drive your desktop or reach production services should stay on GitHub-hosted.
